# Data Model: CombatAction

This document describes the data model for the `CombatAction` entity, which is central to the Natural Language Command Processor feature.

## Entity: CombatAction

The `CombatAction` is a structured JSON object that represents a single, executable action taken by a combatant during a combat round.

### Schema Definition

The structure and validation of this entity are enforced by the `CombatActionSchema` defined in `plugins/game-rule-dnd5e/src/pluginData.ts` using the Zod library.

### Fields

| Field         | Type                                 | Description                                                                                             | Required |
|---------------|--------------------------------------|---------------------------------------------------------------------------------------------------------|----------|
| `actorId`     | `string`                             | The ID of the character or combatant performing the action.                                             | Yes      |
| `actionType`  | `enum`                               | The type of action being performed. Examples: "Attack", "CastSpell", "UseObject", "Move", "Other", etc. | Yes      |
| `targetId`    | `string` (optional)                  | The ID of the target character or object. Required for actions that have a target, like "Attack".       | No       |
| `description` | `string`                             | A brief narrative description of the action, often generated by the AI.                                 | Yes      |
| `spellName`   | `enum` (optional)                    | The name of the spell being cast, required only if `actionType` is "CastSpell".                         | No       |

### Validation Rules

- A `targetId` is required if `actionType` is one of "Attack", "CastSpell", "Help", or "UseObject".
- A `spellName` is required if `actionType` is "CastSpell".

### State Transitions

The `CombatAction` object is ephemeral and does not have its own state transitions. It is created at the beginning of a combat round and used by the `resolveCombatAction` method to mutate the state of the `Battle` and `Combatant` entities (e.g., by reducing `currentHp`).
